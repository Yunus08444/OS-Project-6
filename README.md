## 2. Теоретическая часть

### 2.1. Многопоточность

Многопоточность — это способ организации программы, при котором несколько потоков выполняются в рамках одного процесса.

Потоки имеют общее адресное пространство и могут обращаться к одним и тем же объектам. Это удобно для параллельного выполнения задач, однако при совместном изменении данных могут возникать ошибки.

В Python для создания и управления потоками используется модуль `threading`.

### 2.2. Race Condition — гонка данных

Гонка данных возникает, когда несколько потоков одновременно обращаются к общим данным, и итог зависит от порядка выполнения операций.

Например, операция увеличения счётчика:

```python
counter += 1
```

состоит из нескольких действий: чтения значения, увеличения и записи результата. Если несколько потоков выполняют эти действия одновременно, некоторые изменения могут потеряться.

Для защиты общего ресурса применяется блокировка `Lock`.

### 2.3. Lock — блокировка

`Lock` позволяет только одному потоку одновременно выполнять защищённый участок кода.

Пример:

```python
with lock:
    counter += 1
```

Когда поток входит в блок `with`, он получает блокировку. Остальные потоки должны дождаться её освобождения.

### 2.4. Semaphore — семафор

Семафор управляет количеством потоков, которым разрешено одновременно получить доступ к ресурсу.

В данной работе семафоры используются для реализации ограниченного буфера:

- `empty` — количество свободных мест;
- `full` — количество занятых мест;
- `mutex` — защита операций над буфером.

### 2.5. Condition — условная переменная

`Condition` позволяет потокам ожидать наступления определённого условия.

Например, потребитель ожидает, пока буфер станет непустым, а производитель — пока в буфере появится свободное место.

Ожидание условия необходимо выполнять в цикле `while`, чтобы повторно проверить состояние после пробуждения.

### 2.6. Barrier — барьер синхронизации

`Barrier` позволяет нескольким потокам дождаться друг друга в определённой точке программы.

Когда все заданные потоки достигают барьера, они продолжают выполнение. В работе барьер используется для синхронизации нескольких этапов.

### 2.7. Lost Wakeup — потерянное пробуждение

Потерянное пробуждение возникает, когда поток отправляет уведомление до того, как другой поток начал ожидание.

В результате уведомление может быть потеряно, и ожидающий поток останется заблокированным.

Для предотвращения подобных ситуаций необходимо правильно организовывать проверку условия и ожидание с помощью `Condition`.

## 4. Выполнение практической работы

### Задание 1. Демонстрация Race Condition

В файле `race_condition.py` создаётся несколько потоков, которые изменяют общую переменную-счётчик.

Каждый поток выполняет определённое количество операций увеличения счётчика. При отсутствии синхронизации возникает риск потери обновлений.

В программе рассматривается ситуация совместного доступа к общей переменной.

Важно отметить, что в CPython наличие GIL может влиять на наблюдаемый результат. Поэтому отсутствие расхождения в конкретном запуске не означает, что логическая проблема гонки данных отсутствует.

### Задание 2. Исправление Race Condition

В файле `race_fixed.py` используется блокировка `threading.Lock`.

Перед изменением общего счётчика поток получает блокировку. После завершения операции блокировка автоматически освобождается.

Таким образом, участок кода, изменяющий счётчик, выполняется безопасно.

В программе используется четыре потока, каждый из которых выполняет 100 000 увеличений.

Ожидаемый итог:

```text
400000
```

Результат проверяется с помощью утверждения `assert`.

### Задание 3. Ограниченный буфер с семафорами

В файле `buffer_semaphore.py` реализован ограниченный буфер, который используется несколькими потоками-производителями и потоками-потребителями.

Размер буфера ограничен пятью элементами.

Производители добавляют элементы, а потребители извлекают их. Семафоры регулируют количество свободных и занятых ячеек.

В программе используются:

- три потока-производителя;
- два потока-потребителя;
- буфер ёмкостью пять элементов;
- семафоры `empty` и `full`;
- блокировка `mutex`.

После завершения работы проверяется, что все произведённые элементы были обработаны, а буфер остался пустым.

### Задание 4. Ограниченный буфер с Condition

В файле `buffer_condition.py` реализована альтернативная версия ограниченного буфера.

Вместо семафоров используются:

- `threading.Condition`;
- блокировка;
- очередь на основе `collections.deque`.

Производитель ожидает, если буфер заполнен. Потребитель ожидает, если буфер пуст.

После изменения состояния буфера потоки уведомляют ожидающие стороны.

Данная реализация демонстрирует применение условных переменных для организации взаимодействия между потоками.

### Задание 5. Синхронизация через Barrier

В файле `barrier_demo.py` создаются четыре потока.

Каждый поток выполняет несколько этапов работы. Перед переходом к следующему этапу потоки синхронизируются с помощью объекта `threading.Barrier`.

Барьер гарантирует, что все потоки достигнут определённой точки, прежде чем продолжат выполнение.

Это позволяет организовать поэтапное выполнение задач.

### Задание 6. Демонстрация Lost Wakeup

В файле `lost_wakeup.py` рассматривается проблема потерянного пробуждения.

Программа демонстрирует, что уведомление, отправленное до начала ожидания, может быть потеряно.

В качестве способа предотвращения проблемы рассматривается правильная организация ожидания условия. Поток должен проверять условие в цикле `while`, а уведомления должны использоваться совместно с механизмом синхронизации.
